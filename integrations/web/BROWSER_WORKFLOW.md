# Browser task behavior

Operator reference only. These directions were placed in the current CVS task
scope, not installed as standing general agent instructions. Automatic approval
review rejected a proposed persistent AGENTS.md rewrite; no such rewrite ran.

When the owner asks you to book an appointment or complete a form, perform the
ordinary website work yourself with the browser tools. Do not turn the assignment
into a manual walkthrough. Ask only for missing facts, necessary authentication
or consent, and exact native approvals required by the tool boundary.

Inspect the live browser first. Use owner-supplied facts and exact field labels to
prepare a bounded web task. Include exact `clicks` grants for known routine controls
on their exact current page URL, such as a non-submit Next button or the owner's
chosen demographic radio. Include only the controls actually seen in the current
snapshot. Custom dropdown choices use the exact options grant. Authentication,
consent, unknown controls and final commitments still need separate review.

After native task approval, read the active task and use web_task_step to enter
approved values and perform granted routine clicks. Continue inspecting and working
until complete, a genuine missing fact, or another required native review. A new
page outside the exact routine-control grant requires a fresh exact review or task
scope; never expand a grant yourself. Never invent medical or insurance answers.

Use private owner takeover for credentials, verification codes and payment details.
Ordinary address, city, ZIP and owner-specified demographic entries are bot work.
For CVS's masked Date of birth field, prepare a separately owner-reviewed click on
the exact Show date of birth checkbox. After native approval reveals that ordinary
date field, enter the approved date with the normal tools. This display-only
exception never authorizes Next, code delivery, passwords or other secret controls.
CVS has a visible Continue as a guest route; the owner chose that route after code
delivery failed. Prefer that supported route rather than repeatedly requesting codes.

New browser sessions last 45 minutes from creation and use metered provider time.
Inspect session status and expiry before requesting approval. Never request approval
for a task whose browser has ended. Do not silently recreate a session or reuse old
task authority after expiry. Preserve uncertain action holds and never repeat an
unconfirmed submission. Obtain exact final booking approval and inspect a real
confirmation before saying an appointment was booked. Close the browser afterward.

Inspect snapshot readiness before treating a page as blocked. Supported public
verification may take time; use one bounded read-only wait, preserve an active
provider solve and avoid immediate closure/handoff. Visible embedded frame sources
are discovery leads, not new action authority; inspect public candidates through
the normal validated browser tools. Another origin needs its own interaction scope.
Browser closure does not cancel a possible website reservation or prove zero
duplicate risk. A phone fallback needs its exact current native review, including
both codes in the full approval line.

For dated travel/research, use a rendered browser when fetch omits JavaScript
content. Verify the owner's exact request against a live matching result. Generic
route advertisements and promotional minimums do not establish dated prices.
If no matching source can be read, report that limitation without substituting
unrelated cheap fares. No flight-data API is connected by the access repair.
